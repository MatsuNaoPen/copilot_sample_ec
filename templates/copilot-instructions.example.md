# プロジェクト全体指示（GitHub Copilot 向け）

> 【研修用テンプレート】ハーネス整備ワークショップで `.github/copilot-instructions.md` として
> 配置する。<角括弧> の箇所は自分たちのチームの言葉で埋めること。
> 原則は「検証可能な粒度」で書く（NG:「高品質に書く」／OK:「外部入力は必ず検証する」）。

このリポジトリは「ECカートの料金計算ロジック」を題材にした Next.js アプリです。
コード生成・補完・チャットでの提案は、以下の規約に従ってください。

## 言語・環境
- フレームワークは **Next.js（App Router）+ TypeScript**。
- テストフレームワークは **Vitest**（`tests/` 配下・node 環境）。
- 料金計算ロジックは **外部 I/O（ネットワーク・DB・現在時刻・乱数・DOM）に依存しない純粋関数**として
  `src/lib/pricing.ts` に置く。UI（`app/`）はこの純粋関数を呼ぶだけにする。

## コーディング規約
- **型を必ず付ける**。関数の引数・戻り値、公開する型は明示する。`any` は使わない。
- 金額は **整数（円）** で扱う。端数は **`Math.floor` で切り捨てる**。
- 計算ロジックを React コンポーネント内に直接書かない（`src/lib/` に分離する）。
- <チーム固有の規約があればここに追記: 命名規則・ディレクトリ規約 など>

## エラーハンドリング
- **例外を握り潰さない**。`catch {}` で握りつぶす実装は禁止。
- 入力が不正なケースは専用のエラークラス `PricingError` を **明示的に throw** する。
  曖昧な戻り値（`null` や `-1`）で異常を表現しない。
- UI 側では `PricingError` を捕捉してメッセージを画面に表示する。

## テスト方針
- **テストファースト**。実装より先にテストを書く前提で進める。
- 正常系・境界値・異常系を網羅する。特に境界値（送料無料のしきい値ちょうど・端数の切り捨て）を必ず含める。
- テストは決定的であること（時刻・乱数・順序に依存しない）。

## ドキュメントとの整合
- 仕様の正本は `docs/requirements.md`（要件）と `docs/design.md`（設計・受け入れ条件）。
- 仕様を変更する実装では、**design.md の該当箇所を同じ PR で更新**する。
- 仕様で曖昧な点は勝手に決めず、Issue のコメントで質問してから実装する。
