# プロジェクト全体指示（GitHub Copilot 向け）

このリポジトリは「ECカートの料金計算ロジック」を題材にした、起動可能な Web サンプルです。
コード生成・補完・チャットでの提案は、以下の規約に従ってください。

## 言語・環境
- フロントエンドは **React 18 + TypeScript**、ビルド/開発サーバーは **Vite**。
- テストフレームワークは **Vitest**。
- 料金計算ロジックは **外部 I/O（ネットワーク・DB・現在時刻・乱数・DOM）に依存しない純粋関数**として
  `src/pricing.ts` に置く。UI（`src/App.tsx`）はこの純粋関数を呼ぶだけにする。
  → ロジックを純粋に保つことで、テストが決定的になりライブデモが安定する。

## コーディング規約
- **型を必ず付ける**。関数の引数・戻り値、公開する型（`Cart` / `CartItem` / `PricingResult`）は明示する。
  `any` は使わない。
- 金額は **整数（円）** で扱う。割引などで端数が出る場合は **`Math.floor` で切り捨てる**
  （例: `Math.floor((subtotal * 10) / 100)`）。浮動小数の誤差を計算結果に持ち込まない。
- 料金計算は副作用を持たせず、入力（`Cart`）から出力（`PricingResult`）を返す形にする。
- UI の状態管理は React の `useState` で十分。計算ロジックを React コンポーネント内に直接書かない
  （`src/pricing.ts` に分離する）。

## エラーハンドリング
- **例外を握り潰さない**。`catch {}` で握りつぶす実装は禁止。
- 入力が不正なケース（数量0以下・単価マイナス・無効なクーポン・会員割引×クーポン併用）は、
  専用のエラークラス `PricingError` を **明示的に throw** する。
  曖昧な戻り値（`null` や `-1`）で異常を表現しない。
- UI 側では `PricingError` を捕捉してメッセージを画面に表示する（握りつぶさない）。

## テスト方針
- **テストファースト**。実装より先にテストを書く前提で進める。
- 正常系・境界値・異常系を網羅する。特に境界値（送料無料の閾値ちょうど、端数の切り捨て）を必ず含める。
- テストは決定的であること（時刻・乱数・順序に依存しない）。
- ロジックのテストは `src/pricing.test.ts` に置き、`src/pricing.ts` の純粋関数だけを対象にする。

## ドキュメントとの整合
- 議事録（`docs/minutes/`）→ 要件定義書 → 設計書 → テスト → 実装、の順で整合を取る。
- 仕様で曖昧な点（例: 端数処理）は勝手に決めず、要件・設計の「不明点」に挙げてから実装する。
